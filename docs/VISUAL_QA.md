# Agrorithm visual and interaction verification

This is a record of observed software behavior, not agronomic validation. The production preview is tested at `/FieldShift/`; the display name is independent of this deployment path.

## Reproducible checks

Run `node scripts/visual-qa.mjs` against the existing production preview on port 4173, or set `VISUAL_QA_URL` to another complete base URL. `--filter=REGEX` restricts cases, for example `--filter=tablet/soil`. The script uses one headless Chromium browser with sequential pages and service workers blocked to avoid stale build assets. It does not operate the user's visible browser.

The matrix covers 1440 × 1000 desktop, 768 × 1024 tablet and 390 × 844 phone viewports. Routes include the opening menu, six Field Studio steps, Agronomist Console, Farmer Companion, satellite atlas, four crop categories, both soil views, sources, help, team and design review. Model checks include three scroll positions, transparent canvas clearing, projected model bounds, annotation bounds/overlap, manual inspection, zoom, reset, ordinary wheel scrolling, Ctrl+wheel, context loss and a deliberately blocked model request. The phone journey verifies a poster appears before explicit 3D opt-in.

The evidence is written to `docs/design/agrorithm/visual-qa.json` and JPEG screenshots. Filtered runs write `visual-qa-targeted.json`; the prior failed baseline is retained under `docs/design/agrorithm/baseline/`. Run `node scripts/visual-qa.mjs --filter=reducedmotion/soil` for the separate demand-rendering inspector check. The script reports failures and exits nonzero rather than weakening checks. Fallback opacity is sampled after the application's fade transition settles.

An additional screenshot review covered Home, Atlas, Soil, Crop models, and Studio setup, scenarios and export: seven pages at all three viewport sizes, top/mid scroll positions, plus open display settings and the alternate `Poster only` quality label. It identified a checkbox width rule that detached residue labels and overlapped delete controls, a five-column override that hid phone/tablet crop dates, a hidden tablet Motion label and dark Home popover/trigger contrast problems. The before screenshots and JSON are retained under `docs/design/agrorithm/spacing/baseline/`.

The fixes in `src/exhibition.css` use a two-column sequence editor below 1101px and for Farmer Companion, with a full-width crop selector, attached residue checkbox/label and a separate 44px delete target. Wide layouts retain five clear columns. The quality pill has a consistent 44px height and centered icon/caret. Home's display popover has explicit readable foregrounds and a visible settings trigger; its Motion label remains visible on tablet. Atlas zoom and context controls now have 44px minimum targets and clear spacing.

`node scripts/spacing-qa.mjs` reran this entire bounded matrix after the fixes: **21 cases, 98 checks, zero failures**, in 63.2 seconds using Chromium 158. It produced 52 screenshots. Date fields measured at least **242.4px desktop, 245.4px tablet and 146.5px phone**, with complete dates visible in the actual screenshots. Residue text stayed inside its label without intersecting the delete target. Quality controls measured 44px with aligned icon/caret centers. Dark Home popover text contrast measured **13.0:1** and its open trigger **9.4:1**. Map targets measured at least 44 × 44px. No horizontal document overflow or unhandled page errors were observed.

All six refreshed top/mid contact sheets and the affected full-size sequence/settings/map screenshots were inspected. The updated desktop/phone Earth was visibly spherical with directional lighting, and the desktop Sun halo appeared smooth. The Atlas had a clean background with no building image. The remaining pages' gutters, card padding, labels and control placement were inspected without further spacing defects. This focused retest supplements the retained 61-case model/route matrix; it does not replace it or claim a physical-device performance measurement. The test supports `--filter=REGEX` for bounded reruns and preserves nonzero failure exit status.

The supplied 1920px screenshot exposed a separate wide-header constraint: the legacy 1600px maximum width left pale gutters on each side of Home's dark header. A header-only override removes that maximum and auto margins without changing the opening/portal geometry. A separate `--filter=wide/home` run passed **seven checks** and its actual screenshot was inspected: header left edge **0px**, width **1920px**, height **106px**, with no pale gutters. The combined spacing evidence is **22 cases / 105 checks / zero failures**. The default spacing script now includes this additional 1920 × 1080 Home case; the original 21-case result and separate wide result remain in their JSON files.

## Measurement limits

Headless Chromium used **ANGLE / Vulkan SwiftShader (Subzero)**, recorded in each JSON model frame. Viewport emulation is not a physical phone test. No frame-rate, integrated-GPU throughput, battery or thermal result is inferred from these checks. Projected bounds measure the conservative geometry envelope rather than only nontransparent pixels. These are local production-preview results, not an observed deployment URL or a live-host check. Software/layout checks do not establish scientific validity or local agronomic suitability.

## Location and date regression checks

The device-location feature is requested only by pressing **Find your farm’s location**. Four production-browser tests passed for the native API with a simulated granted location, a denied-permission fixture, a late callback after manual editing, and stale future date filters plus navigation. The simulated position is test-only, not an observation of the developer or a real farm. Metadata follows the selected point into local JSON/PDF; manually editing coordinates clears stale device provenance. Browser geolocation requires HTTPS (or trusted localhost), browser permission and provider support. See the [Geolocation API documentation](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition).
